# BUG-011: Guide agents on global memory vs project memory

## Intent

**Problem:** The engine already differentiates between global memory (`--scope global`) and project memory (`--scope project`), and `umem context --scope project` already includes relevant global facts alongside local facts. However, the default skill and the host blocks generated by `umem init` do not explicitly teach when an agent should write to each scope. In practice, an agent might save durable personal preferences in the project or fail to save relevant learnings at the end of an activity. Additionally, the default `SKILL.md` needs to respect the Agent Skills naming contract: the skill name must contain only lowercase letters, numbers, and hyphens, and must match the folder name (`use-universal-memory`).

**Approach:** Update the default `use-universal-memory` skill and the UMEM managed blocks of `AGENTS.md`/`CLAUDE.md` to document a simple operational policy: query project context at the start; record personal preferences/durable information reusable across projects in `--scope global`; record repository-specific decisions, architecture, commands, and context in `--scope project`; never record secrets, large dumps, sensitive data, or uncertain facts.

## Product Context

- The PRD defines a dual memory architecture: project/folder-specific Short Term Memory and global Universal Memory focused on behaviors and preferences. [Source: `_bmad-output/planning-artifacts/prd.md`, Technical Constraints & Memory Model]
- FR2 requires logically differentiating repository-specific short-term memory and global long-term memory. [Source: `_bmad-output/planning-artifacts/prd.md`, Functional Requirements]
- FR8 requires automatically configuring instruction files to initialize the use of universal memory after installation. [Source: `_bmad-output/planning-artifacts/prd.md`, Functional Requirements]
- FR13/FR14 require external agents to read updated context and write new facts via MCP. [Source: `_bmad-output/planning-artifacts/prd.md`, Functional Requirements]
- The PRD also describes active confirmation learning at the end of the session, with the agent asking or recording approved durable learnings. [Source: `_bmad-output/planning-artifacts/prd.md`, Innovation & Novel Patterns]

## Current Implementation Facts

- `AssembleContextSummaryUseCase` already includes `project` and `global` facts when the requested context is `project`; global facts appear in the `Universal Preferences` section, local facts in the `Project Summary`. [Source: `src/universal_memory/application/memory/assemble_context_summary_use_case.py`]
- `setup_project.py` creates `.umem/skills/use-universal-memory/SKILL.md`, but the default skill currently only shows examples of `umem remember "..." --scope project --tag <tag>` and must ensure that the frontmatter `name` is `use-universal-memory`, not a human-readable title with spaces/uppercase. [Source: `src/universal_memory/application/onboarding/setup_project.py`]
- `setup_host_use_case.py` injects managed blocks into `AGENTS.md` and `CLAUDE.md`, but the current texts only instruct to consult `umem context`, `umem status`, and the skill; they do not explain the global vs project policy. [Source: `src/universal_memory/application/host/setup_host_use_case.py`]
- Existing tests already verify that the default skill is created, that `AGENTS.md`/`CLAUDE.md` preserve manual content outside the managed block, and that the manifests remain compact. [Source: `tests/application/test_setup_project.py`, `tests/application/test_setup_host.py`]

## Boundaries & Constraints

**Always:**

- Preserve Clean Architecture: text/template changes stay in application/onboarding and application/host; do not add business logic to CLI/MCP adapters.
- Keep `AGENTS.md` compact; use short operational rules and pointers to the skill for details.
- Preserve `<!-- UMEM: START -->` and `<!-- UMEM: END -->` delimiters and the preservation of manual content outside the managed block.
- Preserve the current semantics of `umem context --scope project`: includes project memory and global preferences.
- Protect against secrets persistence: maintain explicit guidance not to record credentials, tokens, env dumps, sensitive data, or uncertain information.

**Ask First:**

- Any change to the public contract of the commands `umem remember`, `umem context`, MCP tools, or scope names.
- Any attempt to create new automation that writes to memory without explicit action from the agent/user.
- Any change that turns `AGENTS.md` into a full memory dump or replicates the entire content of the skill.

**Never:**

- Do not add new storage, new schema, or a new CLI command for this fix.
- Do not duplicate the entire detailed policy in `CLAUDE.md`; it must remain a specific delta and point to `AGENTS.md`/skill.
- Do not relax host validators to accept manifests without operational reference to `universal-memory`.

## User Story

As an agent configured by universal-memory,
I want clear instructions to choose between global memory and project memory,
so that durable user preferences are reused across projects and repository-specific learnings do not pollute the universal memory.

6. Given the default skill, when `.umem/skills/use-universal-memory/SKILL.md` is generated, then the frontmatter contains `name: "use-universal-memory"`, using only lowercase letters, numbers, and hyphens, and the name matches exactly the folder `use-universal-memory`.

10. Given automated tests, when the relevant suite runs, then there is coverage protecting the essential scope texts in the default skill, `AGENTS.md`, `CLAUDE.md`, and the skill name contract.

### Suggested Text Semantics

Use content equivalent to:

```text
Use `--scope global` for personal preferences, communication style, durable user information, recurring habits, and behaviors that should apply across projects.

Use `--scope project` for decisions, architecture, commands, constraints, tasks, bugs, domain, and learnings specific to the current repository.

When starting relevant work, run `umem context --scope project`. During or at the end of the activity, record only short, verifiable, and non-sensitive facts that will be useful later.
```

